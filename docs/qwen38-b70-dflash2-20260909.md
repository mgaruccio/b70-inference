## Fresh primary-source research before implementation

- [XPU DFlash2 issue #55250](https://github.com/vllm-project/vllm/issues/55250):
  the ordinary FP16 target path casts the BF16-trained drafter to FP16 and
  collapses acceptance. BF16 community results are not measurements on this host.
- [Draft config](https://huggingface.co/incoai/Qwen3.8-27B-DFlash2/blob/dedf8df68adfb1afeaf7b7480c0a0243108177b4/config.json)
  explicitly specifies BF16 and `DFlash2DraftModel`.
- [Pinned DFlash2 implementation](https://github.com/vllm-project/vllm/blob/73029d42441321b631779db3475031f5ec26dd6c/vllm/model_executor/models/qwen3_dflash2.py)
  uses learned grouped-convolution and candidate-selector parameters. Correct
  model-config dtype is necessary but not sufficient: shared embeddings/head,
  target auxiliary hiddens, proposer buffers, and selector inputs cross dtypes.
- [Pinned speculative config](https://github.com/vllm-project/vllm/blob/73029d42441321b631779db3475031f5ec26dd6c/vllm/config/speculative.py)
  constructs the draft with the target dtype. The installed source confirms this
  at line 1255; the base proposer also initializes its dtype from the target.
- [XPU RMSNorm fix #579](https://github.com/vllm-project/vllm-xpu-kernels/pull/579)
  fixes stacked 2-D weights reusing row zero. Verify the actual installed operator
  and the serving fallback on XPU, rather than trusting a version string.

## Defined end-to-end process

Environment/preconditions: idle `inference-host` B70, no running containers,
Glimmer stopped, original launcher hash and 275 W cap verified. Keep downloaded
public weights in a separate model directory and mount target/draft read-only.
Only the disposable container's installed Python source receives the overlay.

1. Launch the pinned image with the strict FP16 target alone at 32768 context.
   Confirm `/health` and `/v1/models` identify `qwen38` and the requested context.
2. Exercise the existing public API probe's three natural-stop answer canaries,
   131 finite-logprob token-length boundaries, and eight generated Python
   functions with executable checks in an unprivileged, read-only, no-network
   CPU sandbox. Retain the actual prompts, SSE, token IDs, responses and checks.
3. Run the same inputs with BF16 DFlash2 K7. An eager numerical-audit cell must
   establish actual loaded parameter/activation dtypes and finite internal
   results; synchronized audit timings are **not performance results**.
   Test context RMSNorm with distinct per-layer weights and a zero row against
   an FP32 reference on the actual XPU implementation.
4. Require nonzero draft steps and accepted tokens from `/metrics` deltas during
   real code/prose requests, not initialization. Correct answers with zero
   acceptance do not constitute a working drafter.
5. After correctness, disable audit and compare five measured 512-token code
   and prose requests per family after one warmup. Temperature zero, seed 42,
   non-thinking chat, fixed prompts, no prefix reuse. Report post-first-content
   decode rate, all ranges, output changes and mean emitted tokens per draft
   step (`1 + accepted / steps`). Do not generalize these two prompts to agent
   quality or conflate eager and graph configurations.
6. Inspect KV reservations and attempt the existing exactly 200000-token,
   non-thinking chat-framed retrieval only if the BF16 drafter leaves sufficient
   capacity. First run the same framing at short context. Require exact six-digit
   answer `684219`, natural stop, correct prompt count and finite logprobs.
   A short-context success is not proof of the 200k goal; retrieval is not a
   long-generation throughput benchmark.
7. In a `finally` path stop the owned `qwen38` container. Recheck Glimmer, power
   and persistent launcher. Retain ordinary logs/results outside Git; publish
   only reproducible source, focused tests and the dated conclusions.

Commands are recorded per cell in `launch-argv.json` and `launcher.sh`; API
requests and responses are retained alongside `server.log` and `summary.json`.
